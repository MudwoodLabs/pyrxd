    Downloads are not users

    pypistats' "without mirrors" count still includes CI jobs and other automated installs, among them the clean-environment install the release runbook runs after every publish. A release day therefore always adds at least one download of its own.

    Days with no row

    pypistats returns no row for some days. Those days are drawn as 0.

    Clones mostly measure CI

    Clones count every checkout, including CI runs, mirrors and package bots, and this repository's own workflows. Views and unique visitors are the better signal for people, and even they include some automation.

    GitHub keeps 14 days

    GitHub's traffic API returns only the last 14 days. A daily workflow copies them to the traffic-data branch, so this history starts on 2026-09-01 (seeded on 09-15) and grows from here. PyPI history comes from pypistats, which keeps about 180 days.

    Download

    One file fetched from PyPI, as counted by pypistats.org with mirrors excluded. A person who runs pip install can trigger more than one, and a CI job triggers one every run. It counts fetches, not people or projects.

    Page view, unique visitor

    A page view is one load of a page in this repository on github.com. A unique visitor is a distinct client GitHub counted within that one day. GitHub does not document exactly how it tells clients apart, so treat it as "roughly distinct browsers or accounts."

    Clone, unique cloner

    A clone is one git clone or fetch of the repository. A unique cloner is a distinct client GitHub counted that day, and it can be a person, a CI runner or a bot. Many clones from few unique cloners points to repeated automated checkouts. That is an interpretation, not something GitHub reports.

    Uniques do not add up across days

    Someone who visits or clones on two days is one unique on each. Summing the daily uniques therefore overstates how many distinct people there were. GitHub does not return a distinct count for a longer period, so this page does not show one.

    The newest day is partial

    Traffic for the current UTC day is still accumulating and is replaced with the full day the next time the collector runs. The trend lines above leave it out for that reason.

    7-day average and release ticks

    The 7-day line smooths weekday and weekend swings in downloads. Release ticks mark the publish date, and downloads often rise on those days because the release process itself installs the package.
