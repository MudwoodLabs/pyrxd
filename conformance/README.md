# Radiant cross-implementation conformance vectors

Language-agnostic, versioned test vectors so independent Radiant implementations
(pyrxd, radiantjs, Photonic, …) can **differential-test against the same canonical bytes** rather than
each other's running code. Each file is plain JSON: load it, build the artifact from `params`, and
byte-compare against the expected hex.

## Suites

| File | Covers | Anchor |
|---|---|---|
| `dmint-v2-contract-vectors.json` | The V2 dMint **contract script** for given deploy params, across all 5 DAA modes (FIXED / LWMA / ASERT / EPOCH / SCHEDULE) | One vector is byte-anchored to the first **mainnet** V2 deploy (`source: mainnet:…`); the rest are reference vectors |
| `rswp-order-vectors.json` | The **RSWP swap-order advertisement** (v2 + v3 frames), `MultiTxOutV1` price terms, and swap token-id derivation | Reference vectors byte-derived from the canonical producers/parsers (Radiant-Core `swapindex.cpp`, Photonic builder); the reassembly vector reproduces the Radiant-Core functional test. **No mainnet-anchored vector yet** (tracked follow-up). Guarded by `tests/test_rswp_conformance_vectors.py`. |
| `bip44-derivation-vectors.json` | **BIP32/39/44 key derivation** across the three live Radiant coin types (0 / 236 / 512): seed, master + account + leaf xprv/xpub, P2PKH address, and WIF | **Inverted authority — pyrxd is the CONSUMER here, not the producer.** Expected values come from `bip-utils`, an independent implementation, so the suite can catch a *self-consistent* derivation bug that pyrxd's own goldens structurally cannot. Guarded by `tests/test_bip44_conformance_vectors.py`. |

### `bip44-derivation-vectors/1` — why this suite is inverted

Every other suite here treats pyrxd's output as the standard. This one deliberately does the
opposite. A derivation bug that is *stable and self-consistent* — a wrong coin-type path, wrong
hardened-index math, a serialization slip — produces wrong addresses that **every internal golden
happily passes**, because the goldens were generated by the same code they test. The failure is
silent and the money is gone. Only an outside implementation can see it.

That is not hypothetical: this suite's non-ASCII-passphrase vectors fail 0/11 against pyrxd as it
behaved before #347, and pass 11/11 after — it independently catches the missing BIP39 NFKD
normalization.

**Regenerate out-of-band** (`bip-utils` pins `cbor2<6` while pyrxd needs `cbor2>=6.1`, so it is
deliberately *not* a dev dependency; the committed vectors are frozen and the test needs nothing
extra):

```bash
python3 -m venv /tmp/bip44-refvenv
/tmp/bip44-refvenv/bin/pip install 'bip-utils>=2.12.1,<3.0.0'
/tmp/bip44-refvenv/bin/python scripts/gen-bip44-derivation-vectors.py
```

**Known limit, stated plainly:** `bip-utils` and pyrxd share `coincurve`/libsecp256k1 for EC point
math, so a libsecp256k1 arithmetic bug is invisible to this suite. BIP39 seed derivation and
normalization, BIP32 HMAC/CKD construction, hardened-index math, coin-type path assembly, and
xprv/xpub/address/WIF serialization *are* independently covered.

## Format (`dmint-v2-contract-vectors/1`)

```jsonc
{
  "schema": "radiant-dmint-v2-contract/1",
  "builder": "build_dmint_contract_script(DmintDeployParams(**params))",
  "vectors": [
    {
      "id": "v2-fixed-mainnet",
      "source": "mainnet:<deploy-reveal-txid>:vout0",   // or "reference"
      "params": { "contract_ref": {"txid": "<display-hex>", "vout": 1},
                  "token_ref":    {"txid": "<display-hex>", "vout": 0},
                  "max_height": 10, "reward": 1000, "difficulty": 1,
                  "algo": "SHA256D", "daa_mode": "FIXED", "target_time": 60,
                  "half_life": 3600, "height": 0, "last_time": 0,
                  "epoch_length": 2016, "max_adjustment_log2": 2, "schedule": [] },
      "contract_script_hex": "00d8…"
    }
  ]
}
```

`algo` / `daa_mode` are enum **names**; `contract_ref` / `token_ref` are `{txid (display byte order), vout}`.

## Authority & honesty

pyrxd is the **reference** producer here: its V2 builder is byte-matched to canonical Photonic and to the
mainnet FIXED deploy. `tests/test_dmint_conformance_vectors.py` re-derives every vector from `params` and
fails CI if the builder ever diverges from the published hex — so the JSON cannot silently rot. To
regenerate after an intentional builder change, rebuild each vector with `build_dmint_contract_script`
and bump the schema if the *format* changes (not just the bytes).

> Note: the mainnet **LWMA** deploy (`dea3beb9…`) is **not** an anchor — it predates the upstream
> int64-overflow fix (it lacks the `OP_0 OP_MAX` timeDelta floor), so the current builder correctly emits
> 2 bytes more. Only FIXED is mainnet-anchored; the other modes are reference vectors.
